# OpenTitan serial I/O subsystem design and UVM verification problem

Build a specification-driven design and DV result for the selected serial I/O subsystem. The in-scope IP identities are `spi_host`, `spi_device`, `usbdev`. This is a bounded subsystem exercise using one pinned OpenTitan revision, not a request to implement all of Earlgrey or a claim that this subset is a standalone upstream top-level.

## Input authority and hierarchy

`spec.json` contains unchanged public system/architecture/module/behavior/register documents, normative register configuration, and an explicitly authored integration profile and module graph. The source manifest records which original prose bodies qualify the >512 KiB size floor. System background and whole-top context do not expand the implementation scope. Register HJSON and selected integration context do not count toward that floor. Upstream RTL, existing testplans, UVM code and answer obligations are not part of the exported input.

Use `integration_profile.json` to distinguish normative requirements, selected configuration, external environment assumptions, and proposed design choices. Use `module_graph.json` as an initial shared relationship map; source-check and refine it without silently converting a proposal to a proven contract. TL-UL/comportability documents constrain applicable interfaces; they do not by themselves require redesigning an entire SoC fabric. Retain concrete contradictions, missing dependencies and ambiguity with source anchors. Use the revised benchmark-author contract below for named issues. New gaps require precise local obligations, not blanket source-conflict blockers.

## Required design and verification outputs

1. Import the specification by path through LoopX. Persist every requirement and its provenance; work in bounded contexts and recover from durable state in fresh host sessions.
2. Create one shared module/interface/configuration graph for both tracks. Preserve boundary assumptions, clock/reset domains, address/register contracts, cross-module handshake and error behavior, and any unresolved ownership or composition obligations.
3. Design track: adopt or refine the available microarchitecture, propose explicit choices where the source permits them, and produce reviewable synthesizable RTL or a declared fixed-version IP binding. Produce real elaboration/lint/CDC evidence where tools and complete constraints permit it.
4. DV track: derive TP directly from the same specification and shared contract. Generate UVM transactions, sequencers/sequences, drivers, passive monitors, independent scoreboards, functional coverage, environment, test classes and top-level binding. Cover normal operations, boundaries, backpressure, reset/error paths, and the cross-module scenarios justified by the sources.
5. Join the two tracks only at the same accepted contract/configuration revision. Preserve all required composition work; a fragment is not a completed module. Run simulation only when a complete build and checker contract exists.
6. Report passed, failed, blocked and untested stages separately. Requirement extraction, test counts, generated files and smoke success are not coverage. Declare any percentage only from real simulator evidence using a frozen bin denominator; functional coverage and RTL code coverage are separate metrics.

## Execution and evaluation boundary

Start an installed LoopX capability in this input-only workspace with the selected Codex or TRAE host. Use public `dv_import`, `dv_next`, `dv_claim`, `dv_context`, `dv_submit` and relevant design/DV tools; do not manufacture state acceptance or direct database edits. The fixture is inert and does not automatically invoke models or EDA tools. Raw sessions, candidates, private state and logs belong in the execution workspace, never back in this public corpus.

An evaluator may compare outputs against a separately held pinned upstream reference implementation and verification material. Multiple correct RTL architectures and UVM organizations are acceptable; textual similarity is not the correctness criterion. File-only staging is not a claim of network/filesystem isolation from public upstream answers. Simulator/dependency qualification and any 90% target remain separate execution gates.

## Revised normative exercise contract

Benchmark-author policy: explicit declared field names, bit ranges, access types and selected integration configuration govern over obsolete narrative references. This is an authored exercise policy, not an attributed user instruction or a universal upstream priority rule. Conflicts inside HJSON and behavioral ambiguities use the individually named adjudications; no blanket HJSON-wins rule resolves them. Authored decisions supersede only their stated scope. Preserve original source bytes and provenance. Local open obligations gate only affected acceptance claims. Candidate/golden RTL and UVM are not specification authority. No correction is simulation or coverage evidence.

**[CADENCE execution contract](cadence_contract.md):** Implement the selected subsystem as self-contained synthesizable SystemVerilog with an independent SystemVerilog UVM/SVA environment. Cadence Xcelium/IMC and Jasper/Genus are the execution targets. Upstream RTL, build descriptions and tests are historical comparison material, not required build inputs or an independent golden for this authored contract.

The fixed top, logical bus, digital interfaces, clock/reset domains and physical abstraction in that contract are mandatory input. Use dv_generate_uvm(profile_path='eda/verification_profile.json'); complete and review eda/project.json for the staged Cadence runner. No upstream native build is required. No EDA result is supplied.

The following rules are part of the question. Both RTL and TP/UVM generation must consume the same revision. Each linked correction is also embedded in spec.json with exact source-span targets so bounded contexts receive it alongside affected prose.

- **[SH-01](adjudications/SH-01.md)** (corrected): IDLE uses STATUS.ACTIVE becoming low; READY uses STATUS.READY becoming high. They are distinct event predicates and EVENT_ENABLE fields.
- **[SH-02](adjudications/SH-02.md)** (exercise_convention): For this exercise RXWM is true exactly when rx_depth_words > RX_WATERMARK. Use this strict comparison for STATUS.RXWM and the RXWM event predicate. The author selects the explicit greater-than event definition to adjudicate the conflicting reaches wording inside HJSON; this is not blanket HJSON precedence.
- **[SH-03](adjudications/SH-03.md)** (corrected): During unstalled clock generation T_SCK = 2*(CLKDIV+1)*T_core and T_half_SCK = (CLKDIV+1)*T_core. Interpret waveform time units using this half-period.
- **[SH-04](adjudications/SH-04.md)** (corrected): A running divider timeslice spans CLKDIV+1 core cycles: T_timeslice=(CLKDIV+1)*T_core. FSM updates remain subject to the documented enable/stall conditions.
- **[SH-05](adjudications/SH-05.md)** (corrected): COMMAND.LEN is bits [8:0], range 0..511. A data segment transfers LEN+1 bytes; a dummy segment uses LEN+1 dummy cycles as defined by the field.
- **[SH-06](adjudications/SH-06.md)** (corrected): Quad transfer emits the upper nibble [7:4], followed by [3:0], with the source-defined SD lane ordering.
- **[SH-07](adjudications/SH-07.md)** (corrected): Dual output consumes [7:6], [5:4], [3:2], [1:0] in order for each byte. Each shift consumes exactly two bits.
- **[SH-08](adjudications/SH-08.md)** (corrected): TXSTALL/RXSTALL are diagnostic states and do not directly create an event IRQ. Independently evaluate the declared FIFO and other event-enable predicates.
- **[SD-01](adjudications/SD-01.md)** (exercise_convention): The author adopts the coherent four-byte PAYLOAD_SWAP_MASK/PAYLOAD_SWAP_DATA contract: payload_swap_en enables masked substitution in the first four eligible payload bytes. Unselected bits and later bytes pass through unchanged; shorter payloads only transform bytes actually present. Preserve the documented byte ordering.
- **[SD-02](adjudications/SD-02.md)** (corrected): CMD_INFO.addr_mode refers to ADDR_MODE.addr_4b_en for the configured address-width choice. Bind the actual declared enum values and ADDR_MODE CSR.
- **[SD-03](adjudications/SD-03.md)** (corrected): The declared field is CMD_INFO.read_pipeline_mode[23:22]. Preserve its multi-value enumeration and per-mode timing contract.
- **[SD-04](adjudications/SD-04.md)** (corrected): Upload address presence and width follow the current CMD_INFO.addr_mode enum and ADDR_MODE.addr_4b_en where that enum selects the global width. Upload only the address bytes present in the decoded command.
- **[SD-05](adjudications/SD-05.md)** (corrected): Ingress is 112 32-bit words (448 bytes): payload offset/depth 0/64, command 64/16, address 80/16, TPM-write 96/16, all in words. Egress is 848 words: read buffer 0/512, mailbox 512/256, SFDP 768/64, TPM-read 832/16. Banks have independent address spaces.
- **[CT-01](adjudications/CT-01.md)** (exercise_convention): Use the logical instr_type/cmd_intg/data_intg and rsp_intg/data_intg sidebands with the explicit bench_tl_v1 packed ABI in cadence_contract.md. Historical reserved/parity typedefs do not define this exercise's ABI.
- **[CT-02](adjudications/CT-02.md)** (background_scope): The selected top configuration instantiates uart0..uart3 (four UARTs). UART is whole-chip background and is outside both reduced subsystem DUTs.
- **[CT-03](adjudications/CT-03.md)** (scope_interpretation): The base pinout has 47 muxed pads: IOA=9, IOB=13, IOC=13, IOR=12; direct IOR8/IOR9 are excluded. A 32-bit GPIO vector is not a count of all MIO pads. This constrains AON PINMUX geometry; it is external context in serial-I/O.
- **[CT-04](adjudications/CT-04.md)** (background_scope): The local ROM-key table enumerates seven slots, 0..6. Treat the earlier three-slot count as obsolete background; ROM/key provisioning is outside these exercises.
- **[CT-05](adjudications/CT-05.md)** (scope_interpretation): In serial-I/O use the selected SPI_DEVICE CONTROL modes disabled/flashmode/passthrough with TPM controlled separately. Do not add a legacy Firmware mode without a declared interface. In AON this SPI paragraph is out-of-scope background only.
- **[Q-01](adjudications/Q-01.md)** (exercise_convention): Author convention: CPHA determines the output launch edge (0 trailing, 1 leading); FULLCYC modifies receive sampling latency only, from half a SCK cycle to one full cycle after the corresponding launch. Preserve CPOL edge polarity. This chooses the field's sampling-only description; it is not a proven upstream implementation property.
- **[Q-02](adjudications/Q-02.md)** (exercise_convention): Chip selects are zero-indexed. For this exercise valid CSID satisfies 0 <= CSID < NumCS; CSID=NumCS is invalid and follows the declared CSIDINVAL error handling.
- **[Q-03](adjudications/Q-03.md)** (exercise_convention): Require accepted command conservation, ordered completion and correct READY/backpressure. Freeze candidate capacity/initial state; a universal sixth/seventh-command first-stall cycle is outside this exercise's acceptance model.
- **[Q-04](adjudications/Q-04.md)** (exercise_convention): Use staged SW-to-SPI delivery and atomic committed status at eight-SPI-clock byte boundaries. Hardware set wins over SW clear of the same status bit at one commit; distinct bits update independently. Passthrough gating changes at CSb release. The running-domain delivery bound is in cadence_contract.md.
- **[Q-05](adjudications/Q-05.md)** (scope_interpretation): Apply the control-endpoint post-SETUP special case separately from ordinary OUT flow control: after SETUP clears protocol stall, the guide's set_nak_out/rxenable_out conditions hold subsequent IN/OUT requests in NAK until software prepares the control transfer. Do not extend that special condition to every endpoint/transaction.
- **[Q-06](adjudications/Q-06.md)** (scope_interpretation): Model synchronous accesses at each SRAM port. For this exercise the functional bus/USB clocks share the documented 48 MHz input; preserve their port/domain identities and the separate wake clock. Clock gating and wake handoff still require explicit CDC/reset analysis. The phrase asynchronous dual-port does not require asynchronous read data or unrelated functional frequencies.
- **[D-02](adjudications/D-02.md)** (exercise_convention): cadence_contract.md defines bench_tl_v1 field widths/order, CRC7 polynomial, bit iteration, protected words, known vectors, masks and error policy. This logical bus exercise does not claim binary or SECDED compatibility with upstream TL-UL.
- **[N-02](adjudications/N-02.md)** (not_a_conflict): Partition USB transfer expectations by subtype. Apply the declared OUT_ISO behavior to isochronous endpoints and ordinary ACK/NAK rules to the ordinary transaction types for which they are specified.
- **[N-03](adjudications/N-03.md)** (naming_correction): Program the declared PHY_CONFIG.tx_use_d_se0 field. The theory name use_tx_d_se0 is an alias in prose for the same transmit encoding selection, not a second field.
